# Alloy v0.3 strict 七阶段全流程 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** strict 模式升级为七阶段严格全流程（explore→brainstorm→spec→plan→implement→verify→交付），3 个用户门禁、产物全量落盘支持跨会话续跑、四类卡壳现象根治。

**Architecture:** 延续 v0.2"骨架共享+阶段叠加"：orchestrator 原位升级承载七阶段/门禁协议/落盘协议；alloy-subagents 增加 brief 从 plan 派生与超时止损；fast/其余组件不动。纯 markdown 认知层，无代码改动。

**Tech Stack:** Claude Code 插件（commands/ + skills/ 的 markdown 文件）；无新依赖。

**Spec:** [docs/specs/2026-10-20-alloy-v0.3-strict-full-pipeline-design.md](../specs/2026-10-20-alloy-v0.3-strict-full-pipeline-design.md)（执行者须同时读 spec 与本计划）

## Global Constraints

- 七阶段顺序固定：explore → brainstorm → spec → plan → implement → verify → 交付；用户门禁恰好 3 个（brainstorm 末 / plan 末 / verify 末）。
- 落盘目录：`docs/alloy/<YYYY-MM-DD>-<任务slug>/`；文件固定五个：STATUS.md、01-clarifications.md、02-spec.md、03-plan.md、04-verify-report.md。
- 门禁协议五条硬规则按 spec §5 逐字落位；AskUserQuestion 每批 ≤4 问。
- verify 修复循环上限 2 轮；subagent NEEDS_CONTEXT/BLOCKED 无界重派上限 2 次（v0.2 保留）；审查-修复累计 ≥3 轮走 BLOCKED 升级链（v0.2 保留）。
- fast 模式行为与 v0.2 完全一致：四阶段、不落盘、不派发 subagent。
- 全部文档中文；caveman 交付 ≤10 行；版本 0.3.0。
- 每任务完成后 git commit（前缀 feat:/chore:），不 push。

12. `## fast 模式补充`：四阶段原文行为（spec 缺口直接问用户；实现内 TDD 自测；无 plan/verify 独立阶段、不落盘）。
13. `## 跨会话续跑`：新会话"继续 alloy 任务"→ 读 STATUS.md 续跑；零浪费跨会话。
14. `## 降级总表`：v0.2 表格全保留 + 新增 AskUserQuestion 行（不可用时门禁改纯文本清单，仍一次性）。
