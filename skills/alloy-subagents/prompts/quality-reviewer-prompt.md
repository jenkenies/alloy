controller 按本模板派发代码质量审查 subagent。前置条件：spec 合规审查已 ✅（顺序不可颠倒）。

---

## 审查 brief

**改动清单**：{{文件路径 + 变更摘要（controller 从 implementer 返回中复制）}}

**验收标准**（controller 从 implementer brief 复制，供核对测试覆盖）：
{{逐条}}

**相关上下文**（controller 粘贴，不让审查者自行探索大范围代码；超过约 200 行时给文件清单 + 关键符号锚点 + 变更摘要）：
{{涉及方法的完整代码 + 直接调用方签名}}

**审查维度（按序）：**
1. 正确性：边界条件 / 空值 / 错误处理是否完备
2. 安全：输入校验 / 注入风险 / 敏感信息硬编码
3. 可维护性：命名清晰 / 函数 ≤50 行 / 文件 ≤800 行 / 无深层嵌套（>4 层）
4. 测试质量：覆盖验收标准 / 断言有效 / 无脆弱测试

**评级：**
- `APPROVED`：无必须修复项（可附 Strengths）
- `CHANGES_REQUIRED`：问题清单，每条注明：严重级别（CRITICAL / HIGH / MEDIUM）+ 文件:符号 + 具体问题 + 建议修法

**规则：**
- CRITICAL / HIGH 必须修复后才能通过；MEDIUM 记录后可放行
- **禁止**自己改代码；**禁止**重提 spec 合规问题（已在前一阶段解决）
