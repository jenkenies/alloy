# Spec 合规审查派发模板

controller 按本模板派发 spec 合规审查 subagent。审查者只判断"实现是否与 brief 一致"，不评代码风格（那是下一阶段）。

---

## 审查 brief

**任务目标**：{{一句话}}

**验收标准**（从 implementer brief 原文复制）：
{{逐条}}

**改动内容**（controller 粘贴 diff 或变更方法代码，审查以此为准；diff 超过约 200 行时 controller 会改传文件清单 + 关键符号锚点 + 变更摘要，据此定位即可）：
{{diff 或代码}}

**改动范围**：{{改动文件清单}}

**审查指令：**
1. 逐条核对验收标准：已实现 / 部分实现 / 未实现 / 实现-extra（做了 brief 未要求的）
2. 只报告事实，给结论：✅ 合规 或 ❌ 缺口清单（每条注明：缺失项 / extra 项 / 对应验收条目）
3. **禁止**评论代码风格、命名、性能（不属本阶段）
4. **禁止**自己改代码

**返回格式：**
- ✅：`SPEC_COMPLIANT` + 一句话结论
- ❌：`SPEC_GAPS` + 缺口清单（缺失 / extra 分列）
