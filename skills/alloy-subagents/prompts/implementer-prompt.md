## 返回要求

开工前发现 brief 有缺口（验收不明 / 依赖缺失 / 锚点对不上实际代码）→ 直接返回 `NEEDS_CONTEXT`，不必先实现。

实现完成后自审一遍（漏项 / 越界改动 / 测试覆盖），然后返回：

1. **状态**（四选一）：`DONE` / `DONE_WITH_CONCERNS`（附 concerns） / `NEEDS_CONTEXT`（附缺失项清单） / `BLOCKED`（附原因与已尝试）
2. **改动清单**：新增/修改的文件路径 + 每处一句话说明
3. **验证结果**：验证命令实际输出摘要（通过/失败项数）
4. **自审发现**：发现并已修复的问题；未处理的留给审查
